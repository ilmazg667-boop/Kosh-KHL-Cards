# 🏒 Kosh KHL Cards — расширенная версия Telegram-бота

Это расширенная основа обычного Telegram-бота на Python и aiogram 3. Mini App не используется. Проект разделён на два процесса: бот обрабатывает сообщения и кнопки, отдельный worker симулирует матчи, отправляет текстовую трансляцию и завершает аукционы.

## Что включено

- Регистрация, стартовый набор: 5000 🪙, 20 💎 и 6 стартовых карточек.
- Коллекция и состав из LW/C/RW/LD/RD/G. Карточку можно поставить только на её позицию; сила — округлённое среднее OVR.
- Десять редкостей с непересекающимися диапазонами OVR, шесть типов паков и вероятности до открытия. Шансы и цена настраиваются администратором.
- PvE по лигам, обычный PvP, рейтинговый поиск по лиге, вызов игрока по ID со ставкой.
- Автоматические матчи: 60 минут, овертайм 3 на 3, буллиты, события и текстовая трансляция. Состояние матча хранится в БД и продолжается после перезапуска worker.
- Монеты и алмазы, ежедневная награда, рейтинг, квартальные сезоны.
- Рынок без комиссии, прямой обмен один-к-одному, аукционы по заявке игрока с запуском администратором и комиссией 10%. В аукционах повторная ставка текущего лидера учитывает возврат его прежнего эскроу; возвраты, удержание ставки, выплата продавцу и комиссия записываются в ledger. Закрытие лота защищено повторной проверкой статуса и блокировкой строки.
- Ежедневный общий турнир, кланы и клановые битвы, задания и Battle Pass на 100 уровней.
- Админ-команды для валюты, карточек, паков, CSV-импорта, аукционов, банов, статистики, сезонного рейтинга и Battle Pass.
- PostgreSQL, Redis и Docker Compose для развёртывания.

## Запуск локально

1. Распакуйте архив и перейдите в каталог проекта.
2. Скопируйте `.env.example` в `.env`.
3. В `.env` укажите токен Telegram-бота из BotFather и свой числовой Telegram ID в `ADMIN_IDS`.
4. Установите Python 3.11+ и зависимости:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
```

5. В первом терминале запустите бота:

```bash
python -m app
```

6. Во втором терминале из той же папки запустите обработчик матчей и аукционов:

```bash
python -m app.worker
```

Локально по умолчанию используется SQLite. Для worker обязательно задайте тот же `.env` и ту же базу данных.

## Запуск через Docker

В `.env` задайте `BOT_TOKEN`, `ADMIN_IDS` и замените `POSTGRES_PASSWORD` на длинный случайный пароль из URL-безопасных букв и цифр (без символов вроде `@`, `/`, `:`). Затем выполните:

```bash
docker compose up -d --build
docker compose logs -f bot worker
```

Compose сначала запускает одноразовую инициализацию БД, затем PostgreSQL, Redis, бота и worker.

## Реальные хоккеисты и сыгранность

Встроенные карточки помечены `DEMO`: это вымышленные тестовые данные, а не составы КХЛ. Реальную базу нужно загрузить CSV-файлом через бота от имени администратора. Шаблон находится в `data/cards.csv`.

Обязательные заголовки:

```csv
player_name,player_key,position,ovr,rarity,country,club,league,season,image_url,source
```

`player_key` — постоянный идентификатор хоккеиста между карточками разных сезонов и клубов. При переходе в другую команду загрузите отдельную строку карточки; старую не перезаписывайте. `position` — `LW`, `C`, `RW`, `LD`, `RD` или `G`. OVR — целое число 50–100. Фото указывайте только при наличии права на использование прямой ссылки.

Для сыгранности загрузите отдельный CSV с заголовками `player_key_a,player_key_b,shared_games`. Учитываются только подтверждённые совместные матчи, не просто пребывание в одном клубе. Шаблон — `data/chemistry.csv`.

Карточка Семёна Кошелева 99 OVR на 100 уровне Battle Pass не подделывается: администратор должен предварительно загрузить проверенную карточку этого игрока с правильной позицией.

## Границы этой версии

Это расширенный MVP-код, но не завершённый коммерческий сервис с независимым аудитом. Нет готовой лицензированной базы игроков и фотографий, платёжной интеграции, веб-админки, автоматических миграций существующей БД, антифрода/лимитов запросов, мониторинга и нагрузочного/безопасностного аудита. Один аукционный лот поддерживает одного победителя, обмен — одну карточку на одну. Перед публичным запуском импортируйте проверенные данные, настройте резервное копирование, добавьте миграции и проверьте работу на тестовом сервере.
